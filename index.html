Private deployment plan

The production version should be server-backed

Recommended shape

  • Host the dashboard and a small read-only REST API on a private DigitalStudioz HTTPS subdomain.
  • Store provider keys in encrypted server secrets—not in HTML, JavaScript, Drive, or the bridge.
  • Give Trinity and Ravyn separate revocable bearer tokens with read-only scopes, audit logs, and rate limits.
  • Use API keys only for the three supported balance pulls. Never share general account passwords.
  • Normalize each live provider into one safe response: balance, usage period, refresh time, and connection health.
  • Keep Higgsfield API and subscription services manual until official read-only account endpoints exist.

Good next additions

  • Per-provider spending caps and low-balance warnings.
  • Model-level cost history for image, video, and LLM generations.
  • Promo-credit expiration dates and subscription renewal reminders.
  • A sanitized export for Cursor that contains connection names and settings, never secret values.
